⚠️ Do not use temporary AWS STS tokens for deployment. STS session tokens expire every few hours and will cause the bot to stop responding. You must use permanent IAM credentials — covered in Step 1.
1

Get Permanent AWS Credentials

The bot uses AWS Bedrock to run Claude AI. You need a permanent IAM access key — not a temporary session token.

  1. Go to AWS Console → IAM
  2. Click Users in the left sidebar → select your user
  3. Click the Security credentials tab
  4. Scroll to Access keys → click Create access key
  5. Select Application running outside AWS → Next → Create
  6. Copy the Access key ID and Secret access key — you won't see the secret again
ℹ️ Make sure this IAM user has the AmazonBedrockFullAccess policy attached, and that Claude models are enabled in your AWS region (ap-southeast-1). Check this under AWS Console → Bedrock → Model access.
✅ You will paste these into Railway in Step 4. Never commit them to Git.
2

Push the Project to GitHub

Railway deploys directly from a GitHub repository. Create a private repo so your code stays secure.

  1. Go to github.com/new
  2. Name it (e.g. webot-support-bot), set visibility to Private, click Create repository
  3. In your terminal, run the commands below from inside the project folder
# Navigate to the project folder
cd /path/to/tg-intercom-bridge

# Stage all files (.env and runtime data are excluded by .gitignore)
git add -A

# Commit
git commit -m "Initial deployment commit"

# Add your GitHub repo as the remote (replace YOUR_USERNAME)
git remote add origin https://github.com/YOUR_USERNAME/webot-support-bot.git

# Push
git branch -M main
git push -u origin main
ℹ️ The .gitignore already excludes .env, node_modules/, and all runtime data files (conversation logs, mappings, etc). Only source code and the knowledge base are committed.
3

Deploy on Railway

Railway auto-detects Node.js, installs dependencies, and runs npm start.

  1. Go to railway.app and sign in with GitHub
  2. Click New Project → Deploy from GitHub repo
  3. Select your webot-support-bot repository and click Deploy Now
  4. Railway will start a build — you can watch the logs in real time
  5. The first deploy will fail — that is expected because environment variables are not set yet. You will fix that in the next step.
ℹ️ Railway uses the railway.toml file already in your project. It sets the start command to npm start and configures the bot to auto-restart on failure.
4

5

Verify the Deployment

Once the logs show a successful start, test the bot end to end:

  1. Open Telegram and find your user-facing bot
  2. Send /start — you should see the welcome message with the menu buttons (Browse FAQs, Business Partnerships, Leave Feedback)
  3. Ask "what is webot" — the bot should reply with the FAQ answer in English
  4. Ask "what are the withdrawal fees" — the bot should reply with the formatted fee table in a monospace code block
  5. In the agent group, send SESSIONS — the agent bot should reply listing active tickets (or say none)
✅ If all five tests pass, your bot is live and running 24/7 on Railway.
ℹ️ Updating the bot: Push any code change to GitHub — Railway auto-deploys within seconds. To update the knowledge base only, edit data/knowledge-base.json, commit, and push.
!

Troubleshooting

SymptomLikely causeFix
Bot does not respond at all Wrong TELEGRAM_BOT_TOKEN or polling conflict with a local instance Check Railway logs for errors. Stop any locally running instance of the bot first.
Bot replies in Chinese or transfers to human agent for simple messages like "hi" AWS credentials invalid or expired Double-check AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY in Railway Variables. Remove any AWS_SESSION_TOKEN.
Build fails on Railway Node version mismatch or missing dependency Check that package.json has "engines": { "node": ">=18" }. Check the Railway build log for the exact error.
Agent commands not working in the group Wrong AGENT_CHAT_IDS or AGENT_BOT_TOKEN Send /chatid in the group to get the correct chat ID. Make sure it matches the value in AGENT_CHAT_IDS.
Knowledge base changes not showing Updated file not committed and pushed Run git add data/knowledge-base.json && git commit -m "Update KB" && git push. Railway redeploys automatically.
Conversation history lost after redeploy Railway has an ephemeral filesystem by default Expected for now. Add a Railway Volume for persistence once you move past testing.
